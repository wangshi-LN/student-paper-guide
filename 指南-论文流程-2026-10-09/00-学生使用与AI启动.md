# 00 学生使用与 AI 启动

## 获取指导包

推荐首次克隆仓库，后续拉取更新。仓库地址由导师提供，电脑需要已有 Git，并具有仓库访问权限。暂不使用 Git 时，可下载导师提供的 ZIP，解压到独立位置作为备用方式。

在研究工程目录之外打开终端，将下面的仓库地址、论文简称和创建日期替换为实际内容，再执行：

```text
git clone "导师提供的仓库地址" "指导包-论文简称-YYYY-MM-DD"
```

目标目录应尚未存在。成功后进入新目录，应能看到 README.md、AGENTS.md 和 VERSION。已有本篇论文的副本时，按[提交与版本更新](06-提交与版本更新.md)继续维护。[GitHub 官方克隆说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)

每篇论文使用一份独立副本，与研究工程互不包含。论文编号由导师指定；尚未指定可暂用论文短标题区分。

## 从项目路径开始

把本地项目的完整路径交给 AI，补充已知的主稿位置和最近导师意见。AI 必须能访问这些路径；无法访问时先说明缺口，不假装已经读取。

先只读查看项目说明、文件清单和少量关键材料，已有任务状态时一并核对。此时不搬动工程，也不提前把整套材料复制进指导包。

AI 的状态介绍尽量只说四项：

- 实际读到了哪些材料。
- 初步判断处于什么阶段，依据是什么。
- 哪些材料缺失或版本待确认。
- 学生可以选择哪些下一步动作。

学生据此决定继续整理、补材料、开展其他任务，或暂不推进。阶段不确定时可以保留“待确认”。

## 学生确定本轮沟通目的

用一两句话写清：**这次希望老师帮助判断什么，自己准备让 AI 完成什么。**

例如：“目前已有完整初稿，但这次只想请老师判断数据划分是否合适，请整理相关说明和证据。”这属于专题请教，不必自动准备整套初稿交付。

当前论文阶段与本轮沟通目的分别记录；若学生已经说明目的与动作，按该决定继续。目的明确后，AI 选择相关模板、栏目和材料，复制必要文件并加工交付副本，记录来源及版本。原工程保持原位。

## 按需建立交付子文件夹

学生确定目的并选择整理交付后，在指导包副本内沿用或建立交付子文件夹。日期按实际创建时的北京时间填写；以下只是结构示例，不包含真实文件：

```text
交付材料-个人论文-2026-10-09/
├─ 任务状态.md
├─ 导师反馈-审稿意见-2026-10-09/
└─ 提交包-P001-v01-2026-10-09/
```

- 将任务状态与本轮适用模板复制到此处填写，通用指南和空白模板保持原样。
- 本轮提交包目录在人工确认前作为材料整理区，不表示已获准打包或提交。来源文件、工程版本和复制后的用途记在现有记录中。
- 只复制与本轮目的有关的稿件、证据和必要工程附件。原始数据、代码和环境不整体迁入；原工程不因交付整理被移动、删除或回写。
- 导师反馈及各轮版本持续留存。已有旧版个人工作区时先核对位置与版本，保留历史，不因升级自动搬动或删除材料。

本地任务状态记录源工程位置；交给导师的材料应提供可找到的附件或证据位置。交付子文件夹不属于指导包的 Git 版本记录，需独立留档和备份。

## 给本地 AI 的启动话术

填写项目路径后，可复制以下话术；已有本轮目的时直接补充：

> 我正在使用学生论文交付指导包。本地研究项目路径是〔填写完整路径〕。请先读本包 README.md、AGENTS.md 和启动指南；已有任务状态时一并核对。先只读盘点关键材料，简短告诉我读取范围、初步阶段、缺口和可选动作。我决定下一步和本轮沟通目的后，再按需复制材料并按模板加工，保留原工程。材料完成后先自查，再交我审核；只将我明确确认的版本打包，由我通过约定渠道发送。若我已给出本轮目的与动作，请按该决定继续。

## 使用普通聊天 AI

不能直接读取本地文件时，由学生提供当前任务所需的规则、文件内容和材料；按课题允许的范围使用所选服务。AI 说明实际可读范围，学生负责保存文件和核对位置。

不能生成文件或压缩包的工具，应给出清晰的材料与打包清单，由学生操作，不将“已给出文本”写成“已保存”或“已打包”。

## 自查、人工审核与交付

1. AI 自查目的是否得到回应、证据与版本是否一致，列出未核实事项。
2. 学生查看实际稿件、适用的 PDF 和清单，核对事实与表达；需要修改时返回整理，再次自查。
3. 学生明确确认后，AI 按该版本打包并检查包内文件一致；若内容变化，重新审核。
4. 学生通过约定渠道发送，AI 获知真实发送信息后更新本地任务状态。

流程状态统一为：**待学生决定 → 整理中 → 待人工审核 → 待打包 → 待发送 → 已提交**。AI 自查记录与科研验证分开；人工确认不代表导师接受。具体检查和版本维护见[提交与版本更新](06-提交与版本更新.md)。
