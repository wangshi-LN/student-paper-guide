# 06 提交与版本更新

## 本轮需要交什么

先记录学生选择的动作与本轮沟通目的，再结合论文阶段确定材料范围；目的不明确时停在“待学生决定”。AI 先只读盘点，正式复制和加工放在学生决定之后。

第 1 阶段“创新点与实验设计讨论”的新模板已确认；第 2 阶段已确认 Word 格式，具体栏目仍待讨论。其余阶段新模板待讨论，下表相应任务沿用原约定供参考，旧文件编号不代表新阶段编号；第 5 阶段“审稿与审稿回复”本轮不新增材料要求。导师已明确要求的材料不能自行省略。

| 交流任务 | 当前交付约定 |
|---|---|
| 创新点与实验设计讨论 | 一份完整讨论文档，参考文献和图表集中其中 |
| 实验进展与结果汇报 | 一份 Word（`.docx`），图片嵌入正文，不提交 PDF；栏目待讨论 |
| 完整初稿审阅（原约定参考） | 初稿提交说明；可编辑稿件源文件；同版 PDF；说明中列出的必要补充材料 |
| 导师意见修改复核（原约定参考） | 逐条修改说明；可编辑修订稿源文件；同版 PDF；核对修改所需的新增材料 |
| 投稿前整稿确认（原约定参考） | 投稿前检查表；准备投稿的稿件源文件和同版 PDF；目标刊物实际要求的文件 |

第 1 阶段不另行强制提交说明、清单、PDF 或附件；选填栏目可省略，必填内容未知时写“待讨论”并列出具体疑问。其他专题请教仍按本轮目的选择必要内容，不因论文阶段强制交整篇。

第 1、2 阶段的提交清单、自查、来源、确认和打包记录留在本地，可直接记在任务状态，不必另建文件；[提交清单模板](../模板-学生材料-2026-10-09/06-提交清单模板.md) 供核对参考。其余任务继续沿用随材料提供本轮提交清单的原约定，写清沟通目的、主文件和未完成事项，具体简化方式待后续讨论。任务状态默认留本地，导师明确需要时只提供人工确认时副本。

正式整稿审阅中的“可编辑源文件”可以是 Word 或完整的 LaTeX 等工程。后者附必要图片、参考文献文件及构建说明，保证接收方能理解工程。PDF 应由本轮源文件导出；发出前自行打开核对。

## 整理文件与版本

一份提交包只对应一篇论文的一个版本。首次交付可用 v01，后续依次 v02、v03；这与指导包版本 0.4.0 是两套编号。Git 拉取更新的是通用指导包，个人交付材料仍按本地版本留档和备份。

建议文件名：`论文编号-材料名称-v版本-YYYY-MM-DD.扩展名`，例如：

```text
提交包-P001-v02-2026-10-09/
├─ P001-修改说明-v02-2026-10-09.md
├─ P001-论文正文-v02-2026-10-09.docx
├─ P001-论文正文-v02-2026-10-09.pdf
└─ P001-提交清单-v02-2026-10-09.md
```

以上均为命名示例，不代表已存在的文件。尚无正式编号时用论文短标题代替；不要使用“最新版”“最终版2”等难以区分的名称。另有源工程或必要证据时，在相应材料中列清用途。

提交包目录在人工确认前作为本轮材料整理区，确认后才能生成正式压缩包。只复制本轮所需文件，并记录来源、版本与用途；原工程不移动、不删除、不自动回写。补研究或修改原工程需另行明确任务。

后续交付另建版本目录，不覆盖已提交版本。材料中的路径以提交包为起点；本地任务状态记录原工程位置及版本，避免导师收到的材料只写自己电脑上的绝对路径。

## 本地版本记录与持续维护

- 使用版本号和日期区分各轮交付，在已有任务状态的版本记录中写明：依据的导师反馈、本轮主要变化、对应稿件或工程版本、提交状态。
- 工程版本使用能够追溯的现有版本号或研究记录标识；暂时无法确认就写“待核对”，不要自行编造。
- 收到导师意见后保存原反馈，更新当前进度、修改安排和下一步；形成新版交付后补记版本记录。
- 已提交材料保留原样；新一轮在新版本目录中整理。定期备份交付文件夹，包括历轮稿件、导师意见和版本记录。

## AI 自查

1. 材料回答了学生本轮希望导师判断的问题，范围与学生选择一致。
2. 主文件和版本明确；涉及提交说明或附件时核对其对应关系，需要 PDF 时核对与源文件同版。
3. 模板提示已妥善处理。第 1 阶段选填栏目可省略，必填内容未知时写“待讨论”并列出疑问；其他参考模板按适用要求处理。
4. 每项“已完成”和重要结论有对应材料，修改有位置；未验证内容、缺失证据和待讨论问题如实列出。
5. 本轮材料能够对应来源与版本，不混入无关旧稿、缓存、账号信息或整份工程。

自查记录写明实际检查范围、发现的问题和未核实事项。AI 自查不等于复现实验或科研结论已验证。需要修订的内容先处理，再将实际文件和清单交学生审核，状态记为“待人工审核”。

研究问题尚未解决，可以诚实提交当前进展请导师判断；缺少证据不能写成验证通过。必要材料缺失时明确说明影响和补交安排，供学生决定是否按当前范围沟通。

## 学生人工审核

学生查看本轮实际文档、适用的 PDF 或附件，以及本地文件清单，确认事实、表达及沟通目的；第 1 阶段核对完整讨论文档，第 2 阶段核对 Word 及其中的图片。AI 自查后的摘要不能代替实际文件。

学生要求修改时，返回“整理中”，修改后再次自查和人工审核。学生明确确认具体版本及文件清单后，才记为“待打包”；确认记录放在本地任务状态中。

## 按确认版本打包

1. 按人工确认的清单，将同一版本的文件生成交付包；不临时改写正文、重生成不同内容的 PDF 或增减附件。
2. 检查压缩包可打开、文件齐全且内容与确认版本一致；如发现需改内容或清单，回到整理与审核。
3. 核对完成后，在本地任务状态记录包名、对应版本和核对结果，状态转为“待发送”。不向已确认的包内文件追加打包或发送记录。

本地任务状态若被要求随包提交，包内只放人工确认时的副本。正式压缩包不包含无关历史、通用指导包或整个研究工程。

流程状态：**待学生决定 → 整理中 → 待人工审核 → 待打包 → 待发送 → 已提交**。其中“已提交”只根据学生实际发送的信息填写，不等于导师已接受。

## 从哪里提交

**提交渠道：待导师指定。** 由学生通过指定邮箱、教学平台或共享目录发送；AI 不自动代发。学生反馈实际发送信息后，在本地任务状态记录时间、版本、去向及“已提交”状态。

GitHub 不收学生交付物，不要求学生建仓库、push、提 PR 或发 Issue。投稿前检查完成，也不等于已经获准向期刊或会议投稿；按导师确认的安排执行。

## 更新指导包

指导包版本见根目录 VERSION，具体变化见 [更新记录](../CHANGELOG.md)。通用指南目录名称中的日期是建立日期，不因每次内容更新而改名。

### 主要方式：拉取更新

1. 先备份论文交付子文件夹，保留已提交版本。通用指南和空白模板平时保持原样，模板复制后填写。
2. 在克隆的指导包仓库根目录打开终端，确认是导师提供的仓库及约定分支，查看本地状态：

```text
git status
```

3. 确认通用文件没有本地改动后，执行：

```text
git pull --ff-only
```

该命令仅在能够直接接续远程历史时更新；遇到本地分叉会失败。[Git 官方说明](https://git-scm.com/docs/git-pull)

如发现本地修改、分支不符或更新失败，先保留现状并说明原因，再处理；不要强制覆盖、丢弃修改或清理个人材料。模板中误填的内容也应先保留。

4. 更新成功后阅读 CHANGELOG.md 和 VERSION，按需调整当前材料，在任务状态中记录正在使用的指导包版本。论文交付 v01、v02 等继续独立编号；历史已提交材料保留当时使用的指导包版本，不批量重写。

指导包的 Git 历史不记录被忽略的个人交付材料，拉取更新也不等于已经备份这些材料。原研究工程继续保留原位。

### 备用方式：ZIP

1. 下载新版本 ZIP，先解压到独立位置，阅读更新记录，并备份现有交付材料。
2. 只替换旧副本中的 README.md、AGENTS.md、VERSION、CHANGELOG.md、.gitignore，以及“指南”“模板”“示例”三个通用目录；保留论文交付子文件夹和已填材料。
3. 按需调整当前材料并更新任务状态中的指导包版本；不要用空白模板覆盖已填文件，也不改写历史已提交版本。

ZIP 解压目录不能直接使用 Git 拉取更新。以后改用 Git 时，先在独立位置克隆仓库，再复制并核对个人交付文件夹，保留旧副本。

如果新旧规则影响正在进行的导师任务，先保留本轮约定，把差异列给导师判断。学生自己补充的备注放入论文交付文件夹，便于升级时保留。旧版个人工作区中的材料先核对归属和版本，不因升级自动搬动、覆盖或删除工程资料。

## 维护者开发与发布

当前处于本地开发阶段。只维护本开发目录，以 Git 提交保存每轮修改，变更汇总到 CHANGELOG 的“开发中”；不因日常修改生成分发 ZIP 或递增发布版本。VERSION 及模板内现有版本号保留为导入基线，开发完成后统一核对。

开发完成后统一上传 GitHub。发布前逐项核对根目录五个通用文件和三个通用目录中的文件，范围与 .gitignore 的允许清单一致，并检查入口、版本引用及模板修订状态；需要备用 ZIP 时在发布阶段再生成。新增通用文件时同步调整允许清单。

上述规则用于维护通用指导内容。学生对已确认交付物的打包流程，以及发布后克隆、拉取更新和 ZIP 备用的使用说明继续适用。

只发布通用规则、空白模板和虚构或已获准公开的示例。论文交付文件夹、真实论文、研究工程、数据、导师反馈以及原始对话均不属于指导包发布内容。学生收到的指导包应不依赖维护者电脑的路径。
