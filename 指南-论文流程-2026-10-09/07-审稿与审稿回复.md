# 05｜审稿与审稿回复

本阶段分两个环节：收到意见后讨论修改方案；修改后核对稿件与回复。先由 AI 只读盘点原意见、对应稿件及已有材料，再由学生确定本轮环节、目的和范围。尚未修订时可以先讨论方案。

## 本轮交付

沿用论文资源文件夹，每轮另存版本。给导师的材料使用 Markdown 正文、独立图片和相关代码，不要求 Word 或 PDF。

| 文件或资源 | 讨论修改方案 | 核对稿件与回复 |
|---|---|---|
| 00-审稿处理说明.md | 本轮信息、意见理解、拟修改动作、优先顺序与理由、需导师判断的问题 | 本轮修订概况、剩余问题及需导师确认的事项 |
| 01-论文正文.md | 对应原投稿件或本轮指定版本，标明实际版本 | 本轮修订稿，标明与原投稿件的对应关系 |
| 02-审稿意见.md | 完整编辑及各审稿人意见原文与编号 | 沿用本轮完整原意见，不能改写成自己的理解 |
| 03-逐条回复.md | 可暂不提供 | 提供本轮逐条回复、修改位置、证据与未解决原因 |
| 图片和相关代码 | 按本轮讨论范围提供必要副本 | 提供与修订稿、回复一致的副本 |

分别复制[审稿处理说明模板](../模板-学生材料-2026-10-09/07-审稿处理说明模板.md)、[审稿意见模板](../模板-学生材料-2026-10-09/08-审稿意见模板.md)、[逐条回复模板](../模板-学生材料-2026-10-09/09-逐条回复模板.md)，按上表命名。图片使用相对路径引用；代码 README 写明用途、对应结果、运行方式和数据位置，没有相关代码时注明不适用。

## 收到意见后：讨论修改方案

处理说明先写清投稿目标、稿件编号、审稿轮次、对应版本、编辑决定、返修期限（如有）、本轮沟通目的及需导师判断的问题。缺失或不明确的信息如实标记，不自行猜测决定或期限。

审稿意见完整保留编辑决定、要求和各审稿人原文，沿用原编号；没有编号时按原顺序增加稳定的整理编号，并注明出处。中文翻译〔选填〕，与原文分开，不能用摘要或翻译代替原文。原始反馈保留原样。

按优先顺序逐条写“意见编号—理解—拟采取的动作—理由”，让导师判断修改方向、争议和安排。理解与原文区分，计划不写成已完成；完整讨论覆盖编辑及全部审稿人，专题讨论则明确本轮范围。

## 修改后：核对稿件与回复

每条回复固定包含：

1. 原意见编号及原文。
2. 拟提交给编辑或审稿人的回复。
3. 实际修改位置与支撑依据。
4. 尚未解决的事项及原因；没有则写“无”。

完整复核覆盖编辑和各审稿人的意见。对无需改稿或有异议的意见，说明实际处理与依据。回复中声称完成的修改应能在本轮正文、图片、代码或支撑材料中找到；未运行、未验证的内容明确标出，不能为填完回复而虚构结果或自动补做研究。

原送审稿、原始意见和历史版本继续保留，并确认导师能取得复核所需版本。实际期刊上传文件形成后，再按要求核对其中的页码、行号等位置，保持内容与导师确认版本一致。

## 自查与交接

- 投稿信息、编辑决定、期限和稿件版本是否对应本轮原始反馈？
- 编辑及各审稿人的原文和编号是否完整，翻译与自己的理解是否分开？
- 讨论方案是否写明拟采取的动作、优先顺序与理由，未将计划记为完成？
- 修改后回复是否逐条对应实际改动与证据，未解决事项和未核查范围是否明确？
- 正文、图片、代码及回复是否属于本轮版本，路径和定位是否可用？

AI 自查后交学生人工核对实际材料；明确确认后按[提交与版本更新](06-提交与版本更新.md)打包，由学生通过约定渠道发送给导师。来源、自查、人工确认、打包及发送记录留本地任务状态；原研究工程不移动、不删除、不自动回写。

学生确认材料可以发送，不等于导师批准修改方案或返修提交。实际返修上传文件按期刊要求另行准备，并与导师确认内容一致；内容变化时重新确认相关部分，不自动上传到期刊或 GitHub。
