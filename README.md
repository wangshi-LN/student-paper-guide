# 学生论文交付指导包

本指导包用于规范论文各阶段的交付内容，提供操作指南、提交模板和填写示例，可配合自己的 AI 助手使用。

## 当前开发状态

本目录是通用学生指南与模板的唯一开发目录，使用本地 Git 保存修改记录，尚未发布到 GitHub。第 1 阶段模板已确认，第 2—5 阶段继续逐项讨论。

第 2 阶段已确认提交格式：只交一份 Word（`.docx`），图片嵌入正文，不提交 PDF；模板栏目仍待讨论。

日常修改完成并核对后保存为本地提交，不反复生成 ZIP 或递增发布版本。VERSION 中的 0.4.0 是导入基线；当前开发变更看 Git 记录及 CHANGELOG 的“开发中”。全部内容完成后，再统一整理发布版本并上传 GitHub。

## 学生开始使用（发布后）

1. 首次克隆导师提供的仓库，存放在研究工程目录之外；暂不使用 Git 时，可下载 ZIP 并解压。
2. 按[《学生使用与 AI 启动》](指南-论文流程-2026-10-09/00-学生使用与AI启动.md)向 AI 提供本地项目路径，先只读盘点，听取简短的状态介绍。
3. 自己决定下一步和本轮与导师沟通的目的，再让 AI 按需复制材料、选择模板并加工。
4. AI 自查后交你审核；你确认后，AI 按确认版本打包，由你通过约定渠道发送。

后续优先通过拉取更新获取新版指南和模板，具体步骤见[《提交与版本更新》](指南-论文流程-2026-10-09/06-提交与版本更新.md)。

## 注意事项

- **与工程分开存放。** 代码、原始数据和实验环境保留在项目工程目录；论文交付子文件夹用于保存交付材料、导师意见和版本记录。需要附交的工程材料按本轮要求整理。
- **保留通用文件原样。** 指南和空白模板用于同步更新，学生填写复制到交付子文件夹中的模板副本。
- **持续维护。** 收到导师意见或更新交付物后，及时记录当前进度、修改情况和下一步。
- **保留版本。** 每轮使用版本号和日期，如 `v01-2026-10-09`。已提交版本不覆盖，新一轮另存。
- **记录对应关系。** 每版写清依据哪轮导师意见、对应哪个稿件或工程版本，以及本轮主要变化。
- **做好备份。** 定期备份交付文件夹，保留历轮材料。

## 提交要求

第 1 阶段“创新点与实验设计讨论”使用[讨论文档模板](模板-学生材料-2026-10-09/01-研究方案模板.md)，只交一份文档。参考文献和图表集中在其中；选填项可省略，必填项未确定时写“待讨论”并说明疑问。本地任务状态及提交清单用于审核和打包，清单可直接记在任务状态中，不另交老师。

写清本轮沟通目的、已完成内容和未解决事项。专题请教只准备相关说明与必要证据；正式完整初稿、修改稿和投稿前整稿审阅，均附可编辑源文件及同版 PDF；修改稿逐条回应意见并注明位置。导师明确要求的材料不省略。

AI 自查不等于科研验证，内容由学生最终核对。人工确认后不再改写待打包文件；内容有变化时重新审核。

**GitHub 仅用于获取和更新通用指导包。个人交付材料通过导师指定渠道提交。**

新五阶段及模板进度见启动指南；本版只定稿第 1 阶段，其余阶段模板待逐项讨论。
